# SquadVsMonster 기획서 v1.5.0

최신화: 2026-07-03 KST

문제 정의

스쿼드 자동전투와 캐릭터 수집형 전투를 좋아하는 플레이어는 전투를 직접 조작하지 않더라도 “왜 이겼는지”, “왜 졌는지”, “다음 편성에서 무엇을 바꿔야 하는지”를 알고 싶어 한다. 기존 자동전투 게임은 전투가 빠르게 끝나지만, 승패 원인과 스쿼드 조정 이유가 흐리면 플레이어가 다음 빌드를 설계하기 어렵다.

SquadVsMonster는 보스전 특화 세션형 자동전투 게임으로, 스쿼드 편성, 보스 약점, 방벽 생존, 재장전 타이밍을 결과 요약과 다음 조정 제안으로 연결하는 것을 목표로 한다.

주 페르소나

  • 이름: 서유나
  • 나이: 27
  • 직업/라이프스타일: 이동 중과 자기 전 짧은 세션으로 자동전투 RPG를 즐기는 마케터
  • 선호 장르: 스쿼드 자동전투, 캐릭터 수집형 전투, 보스 패턴 공략
  • 현재 행동: 전투 자체보다 편성, 역할 커버리지, 약점 집중, 생존 라인 조정을 비교한다.
  • 사용 맥락: 10~20분 안에 보스전 한 판을 돌리고 결과 요약을 바탕으로 다음 스쿼드를 고친다.
  • 핵심 기대: 승패 후 “강한 유닛이 없어서”가 아니라 “화력/생존/포지션/카운터 중 무엇이 문제였는지”를 알고 싶다.

핵심 루프

유저가 보스와 전장 위험을 확인한다 → 스쿼드 편성과 역할 커버리지를 조정한다 → 자동전투를 실행한다 → CombatAdvisorHUD와 ResultUI에서 승패 원인과 다음 조정을 확인한다 → 다시 스쿼드를 고친다.

30초 플레이 흐름:

  1. 보스 HP, 거리, 방벽, 스쿼드 상태를 확인한다.
  2. 전투 전 조합 프리뷰에서 화력, 방어, 포지션 라벨을 본다.
  3. 전투 중 CombatAdvisorHUD가 약점 집중, 방벽 위협, 재장전 겹침을 안내한다.
  4. 전투 종료 후 ResultUI에서 승리/패배 원인과 다음 조정 한 가지를 읽는다.
  5. 다음 스테이지 또는 재도전 전에 스쿼드 조합을 수정한다.

게임 구성

  • 장르: 세션형 보스전 특화 스쿼드 자동전투
  • 엔진: Unity, Windows 64-bit 빌드
  • 핵심 화면: MenuScene, GameScene, UIScene, ResultUI
  • 주요 시스템: 보스 HP/약점, 방벽 생존, 미니언 웨이브, 스쿼드 멤버 역할, CombatAdvisorHUD, ResultUI 결과 요약
  • 승리 조건: 보스 HP 0 또는 핵심 약점 파괴
  • 패배 조건: 스쿼드 전멸 또는 방벽 붕괴

UI/HUD/UX 원칙

  • ResultUI는 결과 타이틀, 승패 원인, 다음 조정 한 가지를 한 화면에 보여준다.
  • 결과 요약 텍스트는 재도전/다음 버튼과 겹치지 않아야 한다.
  • CombatAdvisorHUD는 전투 중 현재 가장 중요한 위험 또는 기회를 한 줄로 보여준다.
  • 10~20분 짧은 세션 기준으로 결과 확인 후 바로 편성 조정으로 돌아갈 수 있어야 한다.
  • 같은 HUD depth 요소끼리는 겹치지 않는 배치를 기본으로 한다.

다음 스모크 기준

  1. win-by-composition: 승리 요약이 강한 역할 또는 약점 집중 성공을 이름 붙이는지 확인한다.
  2. loss-by-counter: 패배 요약이 카운터 또는 약한 슬롯을 지적하는지 확인한다.
  3. underpower/attrition loss: 다음 조정 문구가 별도 패널 없이 보이는지 확인한다.
  4. ResultUI 텍스트가 목표 해상도에서 버튼과 겹치지 않는지 확인한다.
  5. CombatAdvisorHUD와 ResultUI가 같은 요약 데이터를 사용한다는 흐름을 씬에서 확인한다.

남은 리스크

  • Unity Editor 라이선스 또는 실행 중인 Unity 인스턴스 상태에 따라 자동 테스트/빌드가 막힐 수 있다.
  • 실제 ResultUI 프리팹의 폰트 크기와 앵커 설정은 문서만으로 보장할 수 없다.
  • 프로젝트 방향은 가챠 F2P보다 세션형 보스전 특화로 유지하는 쪽이 현재 포트폴리오 경쟁력에 맞다.
